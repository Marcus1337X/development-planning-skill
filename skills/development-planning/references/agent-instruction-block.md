本项目使用 `development-planning` Skill 管理开发流程。

进行新增功能、修改功能、继续已有开发工作或涉及实现方案的缺陷修复时：

- 优先使用 `development-planning` Skill。
- 开始或恢复开发前执行项目边界校验与开发资料清单校验。
- 读取 `.development/projects.md`，确认由用户手动设置或明确授权 Agent 代为设置的当前项目。
- 开始或恢复开发前，`projects.md` 必须存在且只能有一个 `[✅]` 当前项目；没有 `[✅]` 或存在多个 `[✅]` 时不得开始开发，应提示用户手动调整，或在用户明确授权后由 Agent 代为设置。
- `[✅]` 用于表达用户明确指定的当前项目，防止 Agent 误选或跨项目操作，并保证新会话恢复到正确项目。
- 根据当前项目 `current.md` 恢复开发位置。
- `current.md` 必须记录当前项目、项目开发状态、当前模块、当前模块开发状态、当前功能和最后更新时间。
- `current.md` 必须始终反映实际正在进行的开发位置；实际开发焦点发生变化时应立即同步更新。
- 不得依赖聊天上下文代替 `current.md` 的持续维护；开始或恢复开发前必须读取 `current.md`。
- 当前项目、当前模块、当前功能或对应开发状态发生变化时，按 `development-planning` Skill 的规则更新 `current.md`。
- 每次更新 `current.md` 必须运行 Skill 提供的北京时间脚本刷新最后更新时间。
- 项目开发状态与当前模块开发状态只使用：`从未开始`、`正在开发`、`开发完成`。
- `current.md` 的当前项目必须与 `projects.md` 中唯一 `[✅]` 项目一致；不一致时停止并提示用户确认，不得自行修改。
- 遵循 Skill 定义的开发计划、状态、版本和开发日志规则。

`.development/` 中的文件属于持久化开发状态：

- `projects.md` 中的当前项目只由用户决定：用户可手动设置 `[✅]`，也可明确授权 Agent 代为设置；Agent 不得未经授权自行选择或切换当前项目。
- 每个项目的 `manifest.md` 由 Agent 维护，记录已规划和已确认创建的开发资料。
- 清单项创建前使用 `[]：{相对路径}`；确认文件实际创建成功后改为 `[✅]：{相对路径}`。
- `[✅]` 表示该文件曾经确认创建成功。若后来文件不存在，不得删除该记录或自动重建。
- 检测到 `[✅]` 文件缺失时，停止依赖该文件的开发并告知用户：该文件曾确认存在但当前已丢失；用户可以明确同意后由 Agent 补建。
- 补建只能基于当前仍可确认的信息和对应模板进行，不能保证还原已经丢失的历史内容。
- 正常开发或新会话恢复时，已存在文件必须先读取后维护，不得重新初始化、清空或使用模板覆盖。
- `projects.md` 只追加新项目；`development-log.md` 只追加历史记录。
- 用户询问有哪些项目时，必须读取并完整列出 `projects.md` 中登记的项目内容，不得依赖聊天记忆。
- 用户要求移除项目时，默认只移除 `.development/{项目名称}/` 与 `projects.md` 中对应登记，不得删除真实源码项目目录。
- 项目移除属于破坏性操作，必须先明确列出删除范围并进行第二次确认；未确认不得删除。
- 移除当前 `[✅]` 项目后不得自动选择其他项目；用户可手动选择，或明确授权 Agent 代为设置新的当前项目。

完整流程以 `development-planning` Skill 为准。
